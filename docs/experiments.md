# 実験資料の区分

追加の主実験は[両チーム負荷・周期Wi-Fi・外部BLE](two-team-method.md)です。自チームの指令と大容量通信はSTA→AP→STAを通し、他チームの実通信がある状態を比較します。データは`experiments/data/two-team/`に保存しています。さらに[ESP-NOW指令と外部Wi-Fi](espnow-method.md)を`experiments/data/espnow/`へ追加しています。

以下は構成が異なる先行実験です。旧数値を主実験の条件として読み替えず、補足として参照してください。

# 実験条件と解釈

目的はロボコンで通信設定を選ぶときに役立つ比較データを取ることです。観測PCはIntel BE200、ラップトップ1はIntel AX210、ラップトップ2はMT7921Eを搭載しています。ラップトップ1の有線共有で、観測PCが実験APになってもインターネット接続を維持しました。

操縦はESP32-1への64 byte UDP echoを100 Hz、30秒間送ることで模擬しました。ESP32-2は独立した負荷用APです。ESP32-C5はI/Qの観測用で、操縦端末そのものではありません。両追加ESP32の間隔は75 cm、C5からそれぞれ40 cmと90 cm（どちらの個体に対応するか未確定）、観測PCとラップトップ2は30 cmです。距離を変える比較は実施していません。

操縦比較は56試行、19条件群、送信168,000回、応答167,996回。主要条件は3反復、省電力条件だけ2反復です。SDRは80 MS/s、16,380複素サンプル、8+8 bit、帯域要求48 MHz、固定ゲイン20、FFT 1,024点です。青・緑の図は各条件の反復1、遅延の数値は複数反復を合わせた統計です。

同じAPでの負荷と、別APでの負荷ではAP実装も異なるため、各群の待機条件を基準に比較します。TCPは飽和負荷または速度指定、UDPはアプリケーションへの要求20 Mbpsで、要求通りの送信が実現したとは限りません。送信側socket受付量と受信側アプリケーション到達量を記録し、どちらもPHYの送信量やパケット損失と同一視しません。

期限超過は「RTTが20 msを超えた、または応答が欠落した送信」の割合です。RTTはホストアプリケーション間の往復時間で、ロボットへの片道遅延やモーターの応答ではありません。最大応答間隔もechoの可用性の指標です。

先行観測は51系列・9,140 I/Q取得、受信系補足は64系列・18,400取得です。合計171系列・試行、61,860取得を詳細版へまとめています。PCAPの取得窓照合は真のWi-Fiパケット検出の正解データではなく、時計差と取得開始時刻の不確かさを含みます。STF候補を特定送信機やC5単独の周波数誤差に帰属できません。

入力レベル校正、50 Ω終端、温度計測、実際の移動ロボット、電子レンジの実験は実施していません。測定の限界と結果の詳しい考察は詳細版を参照してください。
