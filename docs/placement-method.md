# 配置・向き・手による遮蔽の比較方法

ROS 2、省電力設定、長時間ESP-NOW19試行の終了・検算後、5配置の短い比較30試行を完了した。基準前は送受信75 cm、C5→指令45 cm、C5→応答95 cmを使用者が報告した。90°回転後の距離はほぼ同じとの申告であり、基準値を用いて再測定値とは区別する。測定中には依頼された変更以外の機器を動かさない。配置を変更したという返答と距離記録がない条件を、自動で測定済みとして作らない。

## 評価する通信

既存の2台でESP-NOWの64 byte指令・100 Hzアプリ応答を測る。同じCh6で別系統Wi-Fiを待機／TCP負荷へ切り替え、配置の違いを比較する。独立した無線のESP-NOW指令とWi-Fi大容量通信の共存を評価する試験であり、この結果からルーター経由Wi-Fiや実ロボットの距離限界を決定しない。

長時間用ファームウェアの連続イベント記録を使い、使用者の要望に合わせて1試行10秒・各3反復とする。評価対象はESP32 2台間のESP-NOWであり、PC間の距離は要求しない。RTT、予定時刻から20 ms以内の応答がない割合、連続欠落、新しいsequenceが更新されない最長時間を記録する。各反復を別に示し、10秒試行を10分連続試行と同じ耐久性の証明として扱わない。Wi-Fiの要求量と実受信量、接続状態も残す。短い試行内にも新たな受信と負荷の確認を残すため、カウンタ監視は2秒ごととし、長時間試行の10秒ごととは区別して記録する。

## 条件と実際の変更

| 条件 | 変更と確認 | 固定するもの |
| --- | --- | --- |
| 基準・前 | 現在の向きで、2台間とC5から各台の距離を確認 | 全機器の位置と向き |
| 向き | 応答側だけを基準から机面内で90°回す。位置のずれも記録 | 送信側、C5、Wi-Fi端末の位置・向き、2台の距離 |
| 人体遮蔽 | 基準配置へ戻し、使用者の手または身体を2台の間に置く。実際の遮蔽物と位置を記録 | 機器の位置と向き |
| 距離 | 基準の向きへ戻し、USBケーブルが届く範囲で応答側を離す。実際に取れた距離を記録 | 送信側、C5、Wi-Fi端末の位置・向き |
| 基準・後 | 最初の位置と向きへ戻して再測定 | 基準・前と同じ配置 |

人体遮蔽は機器・アンテナを触らずに行う。手で遮った場合は「手による遮蔽」と記録し、全身やロボット筐体の影響を測ったとは記述しない。ケーブル長や机の寸法で配置を作れない場合は、できた条件とできなかった条件を分ける。回転時のUSBケーブルや金属物の位置の変化も結果へ影響し得るので、アンテナの指向性だけが原因と決めない。

各配置でWi-Fi待機／負荷を3反復ずつ測る。5配置がすべて実現できれば計30試行、測定窓は合計5分となる。設定・保存・応答猶予と手動変更の時間は別に必要となる。手動変更の都合で配置はまとめて測るため、配置間の順序は完全には無作為化できない。基準・前と基準・後を比較して経時変動を確かめる。基準が変化した場合は、単に配置だけが原因と結論しない。

## 距離と向きの記録

距離はcmで統一する。アンテナの正確な位置が分からない機器もあるため、基板またはケース中心を基準にして同じ測り方を用い、RFアンテナ間の厳密な距離とは呼ばない。少なくとも次を記録する。

- 送信側と応答側の中心間距離。
- C5から送信側・応答側の中心までの距離。
- 2台の基準姿勢と、基準からの回転角。
- 遮蔽物の種類、どの2台の間に置いたか、機器に触れていないこと。
- Wi-Fi機器とC5を動かしていないか、距離変更後に位置を戻せたか。

現在の「同じ机上・おおむね30 cm」は使用者の概略報告であり、各距離の実測値へ置き換えない。先行の75 cm、40 cm、90 cmをこの比較の値として流用しない。今回の基準は送受信75 cm、C5→送信45 cm、C5→応答95 cm。距離変更は送受信150 cm、C5→応答157 cmで、C5→送信45 cmは固定値を引き継いだ。回転・手による遮蔽・基準復帰の中心間距離は基準概数を引き継いだ値で、再測定値ではない。全30試行で30000件の応答を受信した。

各配置への変更後、私有JSON入力に`configuration_applied: true`と使用者の実際の確認返答、3つの距離、送信側の姿勢、応答側の基準姿勢、回転角、遮蔽の種類を保存する。未確認の入力や未測定距離を含む入力は拒否する。確認返答の原文は公開せず、測定条件の項目だけを公開する。保存済みの同名試行と条件が違う場合は再測定で上書きせず、取得を止めて扱いを確認する。

入力の形式は以下のとおり。この例は距離未記入・変更未確認であり、そのまま測定に使えない。確認後に実際の値と姿勢を記録する。変更後の距離を再測定していない場合は、公開項目`distance_note`にもその旨を記録する。

```json
{
  "id": "baseline-before",
  "source": "user report",
  "distance_reference": "board-or-case-centres",
  "distances_cm": {"sender_echo": null, "c5_sender": null, "c5_echo": null},
  "sender_orientation": "",
  "echo_baseline_orientation": "",
  "echo_rotation_degrees": 0,
  "body_obstruction": {"kind": "none", "between_sender_and_echo": false},
  "fixed_devices_unchanged": true,
  "configuration_applied": false,
  "confirmation": ""
}
```

配置IDは`baseline-before`、`rotated`、`obstructed`、`farther`、`baseline-after`。`rotated`のみ回転角90°、ほかは0°。遮蔽条件では`kind`を実際に使った`hand`または`body`、`between_sender_and_echo`をtrueとする。`fixed_devices_unchanged`は送信側・C5・Wi-Fi端末を動かしていないという実際の確認を記録する。

取得は`run_long_espnow.py --placement <私有JSONのパス>`で1配置の待機／負荷×3反復を行う。長時間試行が終了すると3台目の負荷受信ESP32もSTOPされるため、次の取得前に同じファームウェアのまま再起動し、現在のTCP接続を確認する。実機を開く前にROS 2・省電力・固定配置の長時間試行の完了検算を要求し、手動比較を先に実行しない。`make operational-placement`では確認条件・CRC・全イベント・数値・30試行の行列を検算後に実測図を作成する。

## RSSIとSDRの読み方

RSSIは端末が最後に受け取ったパケットの値と、その後の受信数の増加を保存する。届いたパケットだけの値であり、欠落時の受信強度は測れていない。新たな受信がない区間で、以前のRSSIを新しい観測値として使わない。RSSIが高い条件でも更新途絶がないとは限らないため、期限超過・欠落と合わせて評価する。

C5は従来と同じLO2442 MHz・80 MS/s・アナログ帯域48 MHz・手動ゲイン20、青と緑の共通色尺度で観測する。応答側を動かすと、C5までの距離も変わり得る。色の変化を通信相手のRSSIと同じ量として扱わず、C5と各機器の距離も併記する。間欠取得順を連続時間や占有率へ読み替えない。

最終的には、見えるスペクトルの変化、指令の更新途絶、最新パケットのRSSI、Wi-Fiの実受信を並べる。距離点が2つ程度の場合、伝搬損失の式や到達可能距離を推定するための校正実験とは扱わない。
